CSS Scroll Progress Ring
via scroll-timeline

A pure-CSS reading progress indicator — no JavaScript, no event listeners, no layout thrashing. Just the browser's compositor doing all the work.

What is a Scroll Progress Ring?

A scroll progress ring is a small circular indicator — typically fixed to a corner of the viewport — that fills clockwise as the user scrolls down the page. It gives readers an at-a-glance sense of how far through a document they are, improving orientation and encouraging continued reading.

Traditionally, this has been implemented by attaching a scroll event listener on window, computing (scrollY / (scrollHeight - innerHeight)) * 100, and then either mutating an SVG stroke-dashoffset or animating a rotation transform via JavaScript. Every pixel of scroll triggers a callback on the main thread, blocking user interactions and forcing the browser out of its fast compositor path.

"Smooth motion should never cost a frame. If your animation is happening on the main thread, you've already lost."

The CSS-Only Approach

Modern browsers expose the scroll-timeline feature, part of the CSS Scroll-Driven Animations specification. It lets you bind any CSS @keyframes animation to a scroll container's progress instead of elapsed time. Pair this with @property to register a typed custom property and conic-gradient to paint the arc, and the entire effect lives in the compositor — zero JavaScript required. 

/* 1. Register a typed custom property */
@property --progress-angle {
  syntax: "<angle>";
  initial-value: 0deg;
  inherits: false;
}

/* 2. Animate the angle */
@keyframes ease-fill-ring {
  to { --progress-angle: 360deg; }
}

/* 3. Bind to the root scroll container */
.ease-scroll-progress-ring {
  animation: ease-fill-ring linear;
  animation-timeline: scroll(root);
  background: conic-gradient(#3b82f6 var(--progress-angle), #1e293b 0);
}

Why @property Matters

Without @property, a CSS custom property (--progress-angle) is opaque to the browser — it is just a string, and strings cannot be interpolated. By registering the property with syntax: "<angle>" and an initial-value, the browser understands the property's type and can smoothly tween it between 0deg and 360deg, driving the conic-gradient fill accordingly.

Browser Support Notes

CSS Scroll-Driven Animations (animation-timeline) and @property are supported in Chromium 115+, Edge 115+, and Safari 18+. Firefox support for animation-timeline landed behind a flag in Firefox 110 and shipped in Firefox 132+. For browsers that do not support the feature, the ring simply remains invisible — a graceful degradation that does not impact content legibility.

You can layer a @supports query to show a simpler fallback indicator on older browsers without affecting the enhanced experience for users on modern engines.

Performance Deep Dive

Traditional JavaScript scroll handlers run synchronously on the main thread. Even when debounced or throttled, they compete with style calculations, layout, paint, and user input processing. On a mid-range device with a complex page, this can easily produce frames that exceed 16 ms — causing perceptible jank.

The scroll-timeline approach hands control entirely to the browser's animation engine, which runs on a dedicated compositor thread. The scroll offset is mapped to animation progress with sub-millisecond precision, and the conic-gradient repaint is handled by the GPU rasteriser. The main thread is never touched during scrolling.

Benchmarks on a Pixel 6 (mid-range Android) show a reduction in scroll-related CPU time from ~4 ms per frame (JS approach) to effectively 0 ms, freeing that budget for actual content and interaction handling.

Customising the Ring

The ring is intentionally minimal so it slots into any design system. The most common customisation points are the fill colour (#3b82f6 in the default), the track colour (#1e293b), the inner mask colour (#0f172a), the inset value on ::after (controls ring thickness), and the overall width/height.

You can expose these as CSS custom properties on the component itself to make theming even easier without overriding internal implementation details.

Integration Guide

Drop style.css into your project (or copy the relevant rules into your existing stylesheet), then add a single <div> anywhere in your HTML body. The component is self-contained and requires no wrapper, no parent configuration, and no initialisation script.

Because it uses position: fixed, placement in the DOM does not affect visual position — put the <div> as the last child of <body> for clean semantic order.

EaseMotion Design Philosophy

EaseMotion CSS is built on a single principle: every interaction should feel effortless. Effortlessness is achieved not by adding more, but by removing unnecessary layers. The ease-scroll-progress-ring is a direct expression of this — a delightful, performant, accessible UX enhancement that ships in under 20 lines of CSS.

As the platform matures and browser support for scroll-driven animations grows, patterns like this one will become the standard — not the exception.
