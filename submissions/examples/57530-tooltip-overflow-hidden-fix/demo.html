Tooltip Overflow Clipping Fix

Demonstrating and resolving the CSS issue where absolute tooltips are cropped by parent containers with overflow: hidden using pure HTML and CSS.

1. The Bug (Clipped Tooltips) Broken

Because the parent card uses overflow: hidden and position: relative, absolutely positioned tooltips are cropped by the card's boundary and are completely unreadable.

Standard User Card

A classic user profile dashboard card. Hovering over the buttons triggers absolute tooltips that get cut off by the card borders.

Analytics Overview

An analytics card displaying metrics. Action tooltips at the bottom are truncated, preventing the user from understanding the options.

2. Solution A: CSS Anchor Positioning Modern Standard

By using position: fixed on the tooltip and anchoring it to the trigger via anchor-name and position-anchor, the tooltip completely escapes the parent's clipping context while staying tethered to the trigger.

Modern Anchor Card

Uses CSS Anchor Positioning. The tooltips are rendered in fixed viewport space, rendering above the card even with overflow: hidden active.

3. Solution B: Decoupled Stacking Contexts Legacy-Friendly

We separate positioning and clipping. The outer wrapper is positioned (position: relative; overflow: visible), establishing the containing block for absolute children. The inner wrapper is not positioned but has overflow: hidden. The tooltip escapes the clipping boundaries completely.

Decoupled Card Structure

By keeping the inner wrapper unpositioned (static), tooltips bubble up to the outer container. They render outside the clipping box without breaking on older browsers.

4. Solution C: Viewport Fixed Coordinates Simple Layouts

For static card headers or non-scrolling layouts, setting position: fixed along with predefined vertical viewport margins will prevent clipping inside small, fixed UI areas.

Viewport Fixed Card

Using viewport-fixed coordinates. Useful for standalone application modals or sticky panels that do not shift context on scroll.
