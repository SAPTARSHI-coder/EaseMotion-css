Respecting prefers-reduced-motion

A demo of how EaseMotion-style animation classes should behave for visitors who've asked their operating system to minimize motion — with a live toggle below so you can see the effect without changing any system settings.

Simulate prefers-reduced-motion: reduce Applies the exact same override this page uses for the real OS-level setting.

This also responds automatically to your actual OS setting (macOS: System Settings → Accessibility → Display → Reduce motion; Windows: Settings → Accessibility → Visual effects → Animation effects) — the toggle above is just a faster way to preview it here.

"Reduced" doesn't always mean "none"

The blanket rule below is the right default for decorative motion, but a state change that's communicated only through motion can still need a very short, low-amplitude transition — otherwise reduced-motion users lose the feedback entirely, not just the flourish.

Decorative — fully removed

A bounce or swoop that's purely for visual flair gets disabled entirely under reduced motion. Nothing is lost by removing it.

Copy-ready CSS

Drop this in once, globally, and every animation and transition in your project respects the user's preference automatically.

@media (prefers-reduced-motion: reduce) {
  * {
    animation: none !important;
    transition: none !important;
    scroll-behavior: auto !important;
  }
}
