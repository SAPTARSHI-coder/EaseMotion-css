The Future of Scroll Animations

Replacing heavy JavaScript with native CSS Scroll-Driven APIs.

For years, creating a reading progress bar meant binding an event listener to the window's scroll event. Every time the user scrolled, JavaScript had to fire, calculate the scroll position relative to the document height, and manually update the DOM.

This approach runs on the main thread and can cause layout thrashing, resulting in jittery animations and degraded scrolling performance, especially on low-end devices.

Enter Scroll-Driven Animations

With the introduction of the native CSS Scroll-Driven Animations API, we can now link the progress of an animation directly to the scroll position of a scroll container. This means the browser handles the calculation and rendering entirely on the compositor thread.

By using the animation-timeline: scroll(root block); property, we tell the browser to tie our keyframe animation to the scroll progress of the entire document.

animation: scaleProgress auto linear forwards;
animation-timeline: scroll(root block);

Performance Benefits

Because the animation is decoupled from the main JavaScript thread, scrolling remains silky smooth. Even if the main thread is locked up executing heavy scripts, the progress bar will continue to update perfectly in sync with the user's scroll position.
