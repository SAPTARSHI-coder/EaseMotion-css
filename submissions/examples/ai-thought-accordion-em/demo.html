What is the time complexity of merge sort, and can you walk me through how it works with a concrete example?

AI
→ Breaking the problem into subproblems: merge sort is a classic divide-and-conquer algorithm.
→ Recurrence relation: T(n) = 2T(n/2) + O(n), which resolves to O(n log n) via master theorem.
→ Choosing an array [38, 27, 43, 3, 9, 82, 10] for the walkthrough example. Simple and instructive.
→ Constructing a split tree diagram to make the recursive decomposition visually clear.
→ Merging phase: the merge step is O(n) per level, and there are O(log n) levels — hence O(n log n) total.
▋

Merge sort runs in O(n log n) time in all cases — worst, average, and best. It's one of the most efficient general-purpose sorting algorithms.

Here's a concrete walkthrough with [38, 27, 43, 3, 9, 82, 10]:

// 1. Divide phase
[38, 27, 43, 3, 9, 82, 10]
   [38, 27, 43]   [3, 9, 82, 10]
  [38] [27, 43]  [3, 9] [82, 10]
       [27][43]  [3][9]  [82][10]

// 2. Merge phase (combine sorted halves)
       [27, 43]  [3, 9]  [10, 82]
  [27, 38, 43]  [3, 9, 10, 82]
→ [3, 9, 10, 27, 38, 43, 82] ✅

The key insight is that merging two sorted arrays always takes O(n), and since we split log n times, the total is O(n log n).
