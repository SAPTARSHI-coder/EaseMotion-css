Issue #61607 — Duplicate Keyframe Definitions

ease-kf-fade-in is defined identically in both core/animations.css and easemotion/fade.css. Since fade.css loads after animations.css (via easemotion/all.css), the duplicate in fade.css never actually runs — it's dead weight.

This demo shows a single source-of-truth keyframe (renamed here to demo-fade-in to avoid colliding with the live keyframe) producing the same fade-in effect.

fades in once

Recommended fix: remove the duplicate @keyframes ease-kf-fade-in block from easemotion/fade.css, keeping only the definition in core/animations.css.
