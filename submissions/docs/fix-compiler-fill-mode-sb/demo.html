Compiler Fill Mode Fix

Demonstrates the defensive check for ast.fill in easemotion/engine/compiler.js

The Bug

The original code assumed ast.fill would always be defined:

const fillStr = ` ${ast.fill}`;  // Could produce "undefined" in CSS!

If ast.fill is undefined, the generated CSS would contain the literal string undefined.

The Fix

Added a defensive check to prevent invalid CSS output:

const fillStr = ast.fill ? ` ${ast.fill}` : "";

Demo: Engine Animations

The em="" attribute uses the easemotion engine:

em="fade-in 500ms"
em="slide-up 600ms delay-200ms"
em="zoom-in 500ms spring forwards"

Expected Output

The compiled CSS should be valid:

/* Valid - with fill mode */
._em_a1b2c3 {
  animation: ease-kf-fade-in 500ms cubic-bezier(...) both;
}

/* Fixed - without fill mode (empty string instead of "undefined") */
._em_d4e5f6 {
  animation: ease-kf-slide-up 600ms cubic-bezier(...) 200ms;
}
