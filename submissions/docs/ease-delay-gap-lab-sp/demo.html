What are delay classes?

Every ease-delay-* utility class sets a single CSS custom property, --ease-delay, to a fixed millisecond value. Any EaseMotion CSS animation utility (like ease-fade-in) reads that property to delay its own start, so delay classes can be combined with any animation class without duplicating rules for every possible timing.

Built-in delay utility classes
Class --ease-delay value Typical use
ease-delay-100 100ms Second item in a tight, fast-moving stagger (e.g. icon groups)
ease-delay-150 150ms Small UI clusters - buttons, chips, badges
ease-delay-200 200ms Card grids and short lists
ease-delay-250 250ms Slightly slower, more deliberate stagger for feature sections
ease-delay-300 300ms Hero sections and page-level entrances 
<div class="ease-fade-in ease-delay-200">
  Second card in the sequence
</div>

Why these animations only play once: without JavaScript, there's no way to add a "replay" button that resets a CSS animation on demand - reloading or revisiting the page is what re-triggers them here. See the README for more on this trade-off.

Custom delays without editing the framework

When none of the built-in steps fit, set --ease-delay directly with an inline style attribute. Because every animation utility reads from that custom property, this works without touching a single line of the EaseMotion CSS source files. 

<div class="ease-fade-in" style="--ease-delay: 375ms;">
  A one-off delay value, set inline
</div>
--ease-delay: 375ms

Custom value

Set inline, entirely independent of the five built-in delay classes above.

Tip: prefer the built-in ease-delay-* classes for anything reused across a project, and reserve inline --ease-delay overrides for one-off cases - this keeps timing consistent and easy to audit later.

Choosing a gap

The right increment between staggered items depends on how many items there are and how much visual weight each one carries.

Do

Use 50-100ms gaps for 3-6 similarly-sized items (cards, list rows, nav links).

Do

Use larger gaps (150-300ms) for a small number of large, high-impact sections.

Avoid

Stacking delay classes on more than 6-8 items - the last items end up feeling like an afterthought.

Avoid

Gaps under 30ms - most viewers won't perceive the stagger at all, so it isn't worth the added property.
