Workaround patterns

100svh

Small viewport — stable when browser chrome appears/disappears. Best for full-screen heroes.

100dvh

Dynamic viewport — tracks visible area. Use when you want chrome-aware sizing intentionally.

-webkit-fill-available

Legacy iOS fallback when dynamic viewport units are unavailable.

env(safe-area-inset-*)

Pad fixed navbars for notch / home indicator with viewport-fit=cover.

Copy-ready iOS-safe hero CSS

/* viewport-fit=cover required in <meta name="viewport"> */
:root {
  --ios-nav-h: 3rem;
}

.ios-safe-nav {
  position: fixed;
  top: 0;
  left: 0;
  right: 0;
  z-index: 50;
  padding-top: env(safe-area-inset-top, 0px);
  height: calc(var(--ios-nav-h) + env(safe-area-inset-top, 0px));
  background: var(--ease-color-surface, #fff);
}

.ios-safe-hero {
  /* Stable hero — no 100vh jump on iOS Safari */
  min-height: 100svh;
  min-height: 100dvh;
  padding-top: calc(var(--ios-nav-h) + env(safe-area-inset-top, 0px));
  padding-bottom: env(safe-area-inset-bottom, 0px);
}

@supports (-webkit-touch-callout: none) {
  .ios-safe-hero {
    min-height: -webkit-fill-available;
  }
}

@supports not (height: 100svh) {
  .ios-safe-hero {
    min-height: 100vh;
  }
}

/* Pair with EaseMotion entrance */
.ios-safe-hero.ease-fade-in {
  animation: ease-kf-fade-in var(--ease-speed-medium) var(--ease-ease) both;
}

Viewport guidance

Why it jumps

  • iOS Safari's 100vh includes hidden browser chrome area.
  • When the URL bar collapses, layout viewport grows.
  • Fixed nav + tall hero = visible content shift.

Not the animation

  • ease-fade-in draws attention to the jump but isn't the cause.
  • Opacity/transform animations don't change layout height.
  • Fix the viewport units first, then add motion.

Testing checklist

  • Test on real iPhone Safari — simulators miss chrome behavior.
  • Scroll to collapse URL bar; rotate portrait ↔ landscape.
  • Verify fixed navbar doesn't overlap notch content.
