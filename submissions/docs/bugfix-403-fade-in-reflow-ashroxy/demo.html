Performance Investigation & Resolution

The Problem

Originally, the ease-fade-in animation scaled elements by animating the width and height CSS properties. Animating physical geometry on every single frame forces the browser to recalculate the document layout (Reflow) and repaint the screen (Paint). This causes severe frame drops and jank, particularly on mobile browsers and lower-end devices.

The Fix

The fix (implemented in PR #3135) changes the animation to target the compositor thread. By using transform: scale() instead of geometric sizing, the scaling is offloaded to the GPU. The layout tree remains completely unaffected, rendering at a smooth 60fps / 120fps.

Code Comparison

Before (Janky Reflow) 
@keyframes ease-kf-fade-in {
  from {
    opacity: 0;
    width: 0px;  /* Forces layout reflow */
    height: 0px; /* Forces layout reflow */
  }
  to {
    opacity: 1;
    width: 100px;
    height: 100px;
  }
}
After (Compositor/GPU) 
@keyframes ease-kf-fade-in {
  from {
    opacity: 0;
    transform: scale(0.95); /* GPU composited */
  }
  to {
    opacity: 1;
    transform: scale(1);
  }
}
