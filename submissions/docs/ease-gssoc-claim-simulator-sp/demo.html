    GSSoC etiquette

    Claim etiquette

    • Comment before coding — wait for maintainer assignment.
    • Max 2 active issues; quality over quantity.
    • Post progress updates to avoid 24h unassign.

    Submission tracks

    • submissions/examples/ — HTML/CSS components
    • submissions/docs/ — documentation labs
    • submissions/scss/ — mixin partials
    • submissions/react/ — React components

    Review expectations

    • Only the maintainer merges PRs — never self-merge.
    • Squash commits; one clear message per PR.
    • Low-effort spam PRs may be closed without review.
