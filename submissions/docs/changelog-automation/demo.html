Automated CHANGELOG.md Proposal

Using Semantic Release & Conventional Commits

This documentation proposal outlines the integration of semantic-release and commitlint to automatically manage versioning and changelog generation for EaseMotion-css.

Why this is needed:

  • Removes the manual burden of updating CHANGELOG.md.
  • Standardizes commit messages across hundreds of GSSoC contributors.
  • Automatically determines the next semantic version number based on commit types (fix, feat, breaking change).

Proposed Toolchain:

Husky Commitlint Semantic Release GitHub Actions
Note for Maintainers: Because the GSSoC submission bot prevents contributors from directly modifying package.json or .github/ files in pull requests, the full configuration scripts and instructions have been provided in the README.md of this submission directory. Maintainers can simply copy-paste the configuration into the repository root.
