Engine Runtime: process ReferenceError in Browser

Location

easemotion/engine/runtime.js, line 55

Bug

The processElement() function checks process?.env?.NODE_ENV before logging a warning. In browser ESM contexts (no bundler), process is not defined. Optional chaining (?.) protects against undefined properties, not undefined identifiers.

When a user writes em="fly-away" (unknown animation), the engine throws:

ReferenceError: process is not defined

Why This Matters

  • The engine runtime is designed for standalone browser use — the README says "The runtime does NOT require easemotion.css to be loaded — it works standalone"
  • Browsers importing import 'easemotion-css/engine' via native ESM (no bundler) will crash on invalid em="" values
  • The compiler.js already logs unconditionally at line 92 — confirming the guard pattern is unnecessary

Code (Broken)

function processElement(el) {
  const value = el.getAttribute('em');
  if (!value) return;

  const ast = parse(value);
  if (!ast) {
    if (process?.env?.NODE_ENV !== 'production') {
      console.warn(`[EaseMotion Engine] Could not parse em="${value}". Unknown animation name.`);
    }
    return;
  }
  // ...
}

Fix

Remove the guard entirely (simplest approach, matches compiler.js):

if (!ast) {
  console.warn(`[EaseMotion Engine] Could not parse em="${value}". Unknown animation name.`);
  return;
}
